# VibeVoice Realtime — RunPod serverless worker

Low-latency expressive text-to-speech on RunPod serverless, built on
[microsoft/VibeVoice](https://github.com/microsoft/VibeVoice).

Model weights and all 25 voice presets are baked into the image. There is no
cold-start download.

---

## Which model this runs, and which it does not

**It runs `microsoft/VibeVoice-Realtime-0.5B`.** This is the streaming,
single-speaker, low-latency line.

**It does not run `VibeVoice-1.5B`**, the 90-minute four-speaker long-form
model. That is a deliberate exclusion, and here is the reason.

The inference wrapper that drives the 1.5B model,
`VibeVoiceForConditionalGenerationInference`, **is not in the upstream
repository any more**. Checked on 2026-09-21:

| Check | Result |
|---|---|
| Class present on `main`? | No. `modeling_vibevoice.py` defines `VibeVoiceForConditionalGeneration`, which has `forward` but no `generate`. |
| Present in git history? | No. A commit search for the class name returns zero results. |
| Any tag or release to pin? | None. The repository has no tags and no releases. |
| Shipped with the HF weights? | No. `microsoft/VibeVoice-1.5B` contains only weights and config, so `trust_remote_code` cannot reach it. |

Microsoft disabled the repository on 2025-09-05 and later re-enabled it. The
history was rewritten in the process. The 1.5B weights are still public and
still MIT, but the first-party code that runs them is gone.

**If you need the 1.5B long-form path**, the community fork
[`vibevoice-community/VibeVoice`](https://github.com/vibevoice-community/VibeVoice)
preserves `modeling_vibevoice_inference.py`. That is third-party code. It
belongs in a separate image and a separate decision about provenance.

## Licence position

The upstream code is plain MIT. The weights on Hugging Face are tagged MIT and
are not gated.

⚠ **The model card adds prose the licence does not.** It says the model "is
limited to research purpose use", advises against commercial use "without
further testing and development", and forbids cloning a voice without consent.
That prose is a recommendation, not a licence term. It is still a sentence an
opposing lawyer can read aloud. Take legal advice before commercial use.

Microsoft embeds an audible "this segment was generated by AI" disclaimer into
its own generated files. This worker does **not** add one. If your product
needs that, add it deliberately.

## API

Request:

```json
{
  "input": {
    "text": "Hello. This worker is online and speaking.",
    "voice": "en-Emma_woman",
    "cfg_scale": 1.5
  }
}
```

Only `text` is required. Response:

```json
{
  "audio_base64": "UklGR...",
  "sample_rate": 24000,
  "duration_seconds": 3.12,
  "generation_seconds": 0.84,
  "real_time_factor": 0.269,
  "voice": "en-Emma_woman",
  "cfg_scale": 1.5
}
```

The audio is a 24 kHz mono 16-bit WAV. **It is 24 kHz, not 16 kHz.**

## Voices

25 presets ship in the image, across English, German, French, Italian,
Japanese, Korean, Dutch, Polish, Portuguese, Spanish and Indian English.
English names are `en-Carter_man`, `en-Davis_man`, `en-Emma_woman`,
`en-Frank_man`, `en-Grace_woman`, `en-Mike_man`.

Voice matching is exact first, then case-insensitive, then unique substring.
An ambiguous substring returns an error rather than picking one silently.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `DEFAULT_VOICE` | `en-Emma_woman` | Voice used when a request omits `voice`. |
| `CFG_SCALE` | `1.5` | Classifier-free guidance strength. |
| `DDPM_STEPS` | `5` | Diffusion steps per chunk. Upstream default. |
| `ATTN_IMPL` | `sdpa` | Attention implementation. |

⚠ **On `ATTN_IMPL`.** This image ships `sdpa`. Upstream states that only
`flash_attention_2` is fully tested, and that sdpa "may result in lower audio
quality". flash-attn is not an upstream dependency and needs `nvcc` to build,
which the runtime base image does not have. To use it, add a prebuilt
flash-attn wheel to the image and set `ATTN_IMPL=flash_attention_2`. **This is
a stated quality tradeoff, not an oversight.**

## The warm-worker bug this worker avoids

Upstream's demo passes a deep copy of the cached voice prompt into `generate`.
In a script that runs once, that looks like defensive noise. In a warm
serverless worker it is load-bearing: `generate` can mutate the cached prompt,
and the mutation would corrupt every later request off the same loaded model.

This worker loads each preset once as an immutable master and deep-copies it
per request, for both the processor and `generate`. `test_two_requests.py`
proves it by making two requests against one loaded model and comparing them.
A single-request smoke test cannot catch this class of bug.

## Build and test locally

```bash
docker build -t vibevoice-serverless:dev .
```

Run one job through the real serverless entry point, the same command the
container runs in production:

```bash
docker run --rm --gpus all vibevoice-serverless:dev \
    python3 -u handler.py --test_input '{"input":{"text":"Hello. This worker is online."}}'
```

Run the warm-worker probe, which makes two requests against one loaded model:

```bash
docker run --rm --gpus all vibevoice-serverless:dev python3 -u test_two_requests.py
```

Measured on an RTX 4070: cold start to first audio is **12 seconds** end to end,
with weights baked in. See `PROBE_RESULTS.md`.

## Deploying to RunPod Hub

The repository already exists and release `v1.0.0` is already cut. The Hub
indexes releases, not commits, and it needs a public repository.

Two steps remain, both Joel's:

```bash
gh repo edit bojangles1601-wq/vibevoice-serverless --visibility public
```

Then open the RunPod Hub console, choose "Get Started", and give it the
repository URL. The listing then builds, runs `.runpod/tests.json`, and goes to
RunPod for manual review before it appears publicly.
